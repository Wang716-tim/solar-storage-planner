# 项目上下文

## 项目名称

向阳 · 光储估算（仓库名：`solar-storage-planner`）

## 项目愿景

帮助家庭用户在联系安装服务前，用清楚的参数初步比较光伏与储能规模。

## 目标用户

正在了解家庭屋顶光伏、希望核对大致容量和费用的人。

## 核心问题与产品价值

方案参数分散在用电账单、屋顶条件和安装报价中，手算容易遗漏假设。工具将输入、公式和结果放在同一页面，方便调整条件并复核估算。

## 目标技术栈

- 浏览器端：原生 HTML、CSS、JavaScript ES Modules
- 本地服务：Node.js 内置 HTTP 模块
- 测试：Node.js 内置 `node:test`
- 首版不依赖第三方运行时包，不要求云端账户或 API 密钥

## 核心功能

- 输入家庭用电、屋顶面积、发电条件、备用时长和电价。
- 校验输入边界。
- 使用确定性公式估算组件数量、光伏装机、发电量、储能容量和收益。
- 同屏说明计算结果与主要假设。
- 在本机浏览器运行，输入不离开本机。

## 非核心功能

- 现场勘测、并网申请或施工设计。
- 精确逐时天气、遮挡和电价建模。
- 在线账号、数据持久化或远程服务。
- 首版模型调用或自动生成工程结论。

## 当前系统状态

- 版本：0.1.0
- 已实现：本地估算核心、中文响应式页面、本地静态 HTTP 服务和 10 项自动测试。
- 已验证：计算与 HTTP 集成测试通过；窄屏页面与输入错误提示已在浏览器检查。
- 当前里程碑：M2 中文交互页面，已完成。
- 已知约束：输出依赖简化假设，不应作为工程设计或收益承诺。

## 重要技术约束

- 工程估算只能由确定性代码产生。
- 对零值、边界值、缺失值和无效值定义明确行为。
- 不在界面代码中复制计算公式。
- 用户界面使用简体中文。
- 不提交用户账单、密钥或真实场址资料。

## 项目设计原则

准确性和假设透明度优先于功能数量；计算与展示分离；页面可在无外部模型服务时独立运行；输入错误要指出字段和修正范围。

## 已决定不采用的方案

- 不让语言模型直接计算容量、收益或回收期。
- 不在首版接入强制在线的模型服务。
- 不把概算包装成现场结论或收益保证。
