# 技术决策

## Decision 001

Date: 2026-09-25

Problem: 新项目需要让用户快速查看家庭光伏与储能的初步容量和收益估算。

Options: 全托管 Web 服务；带强制模型调用的聊天界面；不依赖第三方包的本地估算页面。

Decision: 首版采用原生浏览器页面、Node.js 本地静态服务和确定性计算核心。

Reason: 输入数据留在本机，安装步骤少，工程逻辑可单测且易于解释。

Trade-offs: 首版交互和计算模型较精简，不提供账户同步和实时外部数据。

Impact: 采用标准 JavaScript ES Modules 与 Node 内置测试，不要求 API Key。

## Decision 002

Date: 2026-09-25

Problem: 如何避免自然语言或模型输出被误认为工程计算结果。

Options: 让模型输出所有结果；用确定性引擎计算，未来如有需要让模型只负责解析输入和解释。

Decision: 确定性引擎是全部数值结果的唯一来源；首版不接入模型。

Reason: 容量与收益可直接复核，不依赖模型稳定性或服务密钥。

Trade-offs: 首版没有自然语言交互。

Impact: 任何后续智能入口都必须使用明确的工具契约，且不得修改计算结果。
